# Фирменный терминальный интерфейс — 4.2.0

В настоящем терминале `mail-radar --menu` показывает рисунок радара и фирменный
логотип MAILRADAR с золотым и бирюзовым акцентами. Крупная блочная надпись
открывается от 96 колонок при высоте от 32 строк; обычное SSH-окно получает
компактный рисунок, чтобы шапка и выбор задачи оставались видны вместе.

От 76 колонок задачи стоят в двух карточках: 1–7 слева, 8–14 справа. В узком
окне — одним списком. От 110×38 добавлены пояснения к пунктам. `?` показывает
справку, `r` заново читает размер окна и перерисовывает меню. Номера 1–14,
выход 0/q и Enter для общего обзора сохранены. После отчёта Enter возвращает
в меню; Ctrl+C завершает сессию. До сбора данных показана выбранная задача.

Статусы подписаны текстом и выделены цветом: OK — зелёный, WARN — жёлтый,
FAIL — красный, UNKNOWN — синий, N/A — приглушённый. Заголовки, Queue ID,
строки ящиков и названия полей также выделены. Сверху отчёта — карточка результата
с периодом, часовым поясом, узлом и фильтрами. Текущая очередь и найденные
Queue ID в истории подписаны отдельно; они не складываются в одну очередь.
Разделители помогают видеть границы источников и проверок. Watch показывает понятные
сообщения о ходе чтения и пробелах источников вместо технического словаря.

Цвет включается только для human output в stdout TTY. Отключение:

```bash
sudo bash ./mail-radar --menu --no-color
NO_COLOR=1 bash ./mail-radar --flow --offline --log ./examples/mail.log
```

Непустой `NO_COLOR` (включая `0`) или `TERM=dumb` также отключает цвета.
Пустой `NO_COLOR` цвет не запрещает. В pipe/файле и JSON/NDJSON нет ANSI.
Цвет не меняет finding ID, данные, выводы, номера пунктов или exit codes.

Реализация — stdlib-модуль `terminal.py` с фиксированной SGR-палитрой.
Размер читается из stdout fd, затем из валидных COLUMNS/LINES; неподдерживаемый
fd не ломает вывод. Ширина считается в видимых ячейках Unicode с учётом
combining и Wide-символов. Длинные адреса, идентификаторы, поля и prompts
переносятся; текст не обрезается ради рамки. На базовом терминале `TERM=dumb`
или при неподдерживаемых символах рисунок/рамки используют ASCII. NO_COLOR
отключает только цвет, а не Unicode. Вывод в файл сохраняет простой формат.

Оформление добавляется после очистки и переноса строк. Управляющие коды из
логов не исполняются; продолжение длинной причины не окрашивается как новый
status badge. Никакие cursor/clipboard/hyperlink escape sequences не генерируются.

Проверки `tests/test_terminal_ui.py` и `tests/test_branded_ui.py`: TTY/env/флаг, nested context cleanup,
одинаковые данные с цветом и без, CSI/OSC/C1/bidi, длинные строки,
TTY JSON/NDJSON, ширины 32/40/80/120 и настоящие PTY-сессии на 32/100 колонках:
возврат, отмена, изменение размера, `r` и справка. Крупный и компактный варианты
проверяются на настоящих PTY-записях, а не на нарисованных макетах.
Результаты полной Linux matrix записаны в [validation.md](validation.md).
Аудит диагностической логики и её ограничения: [mvp.ru.md](mvp.ru.md).
