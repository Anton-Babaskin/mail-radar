# Цветное меню и отчёты — 4.1.2

В настоящем терминале `mail-radar --menu` показывает задачи по группам:
обзор, письма/доставка, SMTP/политика, сервер/домены, поиск/наблюдение.
Номера 1–14 и выход 0 сохранены. После отчёта Enter возвращает в меню;
Ctrl+C завершает сессию. До сбора данных показана выбранная задача.

Статусы подписаны текстом и выделены цветом: OK — зелёный, WARN — жёлтый,
FAIL — красный, UNKNOWN — синий, N/A — приглушённый. Заголовки, Queue ID,
строки ящиков и названия полей также выделены. Watch показывает понятные
сообщения о ходе чтения и пробелах источников вместо технического словаря.

Цвет включается только для human output в stdout TTY. Отключение:

```bash
sudo bash ./mail-radar --menu --no-color
NO_COLOR=1 bash ./mail-radar --flow --offline --log ./examples/mail.log
```

Непустой `NO_COLOR` (включая `0`) или `TERM=dumb` также отключает цвета.
Пустой `NO_COLOR` цвет не запрещает. В pipe/файле и JSON/NDJSON нет ANSI.
Цвет не меняет finding ID, данные, выводы, номера пунктов или exit codes.

Реализация — небольшой stdlib-модуль `terminal.py` с фиксированной SGR-палитрой.
Оформление добавляется после очистки и переноса строк. Управляющие коды из
логов не исполняются; продолжение длинной причины не окрашивается как новый
status badge. Никакие cursor/clipboard/hyperlink escape sequences не генерируются.

Проверки `tests/test_terminal_ui.py`: TTY/env/флаг, nested context cleanup,
одинаковые данные с цветом и без, CSI/OSC/C1/bidi, длинные строки,
TTY JSON/NDJSON и настоящая PTY-сессия с возвратом в меню/отменой.
Результаты полной Linux matrix записаны в [validation.md](validation.md).
Аудит диагностической логики и её ограничения: [mvp.ru.md](mvp.ru.md).
